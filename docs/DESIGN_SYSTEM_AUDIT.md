**Later implementation:** this document records the 27 October audit snapshot. Audit date: 27 October 2026. Scope: the current local React/Laravel source, the supplied overhaul brief and its exact sample data. ### Prioritized backlog

1. **P0 — truth in business state:** distinguish synthetic USD data, stale GPS, provider-pending settlement and proposed policy functions. No destructive or financial prototype action may reach the production API.
2. **P1 — cross-role accessibility:** enhanced contrast pairs, consistent 48px product targets, complete keyboard alternatives for canvas tasks, no critical change lost to polling, screen-reader review of full ordering/booking/payment processes.
3. **P1 — navigation and scale:** preserve six primary admin destinations, role-specific task paths and legacy tools; add server-backed pagination for every currently truncated list. Explicit preview caps are acceptable only when a complete-results destination is available.
4. **P2 — consistent density:** replace ad hoc type/spacing with the shared scale; convert Cashier/KDS/Waiter templates to task-specific organisms rather than cloning the admin dashboard.
5. **P2 — missing backend work:** shift reconciliation, staff-attributed order entry, versioned per-guest deposit/refund policy, outlet tenancy and currency policy. These require domain design, not a CSS patch.

### Atomic component boundaries

- **Atoms:** semantic tokens; Button/IconButton; persistent-label Field; Checkbox/Switch; StatusPill; Currency; DateTime; Skeleton; FocusRing.
- **Molecules:** SearchField, DateRange, FilterChipGroup, MetricCard, QuantityStepper, PriceBreakdown, GPSHealth, SaveStatus. A floating label may animate from an already-visible label, but placeholder text must never be the only label.
- **Organisms:** PaginatedDataTable, OrderCard/Workbench, KdsTicket, CashierBillDrawer, TableMap/ListAlternative, FleetMap, ReservationWizard, DeliveryStepPanel, Notifications, accessible Modal/Sheet.
- **Templates:** public, administrator/manager operations, cashier, kitchen, waiter, rider, customer. Different primary tasks justify different information density while sharing primitives.
- **Data boundary:** domain mappers adapt server snake_case values and prototype fixtures; components consume a documented view model. Do not mix fixture display names with backend enum values or use client totals as settlement authority.

## 5. Interaction/state contract

| State           | Visual and semantic treatment                                                                    | Recovery/verification                                                                                                      |
| --------------- | ------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------- |
| Default         | Persistent label, clear enabled boundary, one primary action per work area.                      | Keyboard and pointer both operate the same action.                                                                         |
| Hover           | Subtle fill/border; no information available only on hover.                                      | Popover remains hoverable, dismissible and present while pointer/focus is inside.                                          |
| Active/selected | Pressed fill; selected filter uses aria-pressed or native checked state; page link aria-current. | Selected state survives refresh only when valid; status wording remains visible without color.                             |
| Focus           | Visible outline with offset; never remove globally.                                              | Focus is not covered by sticky bars, virtual keyboard, drawer or fullscreen map.                                           |
| Disabled        | Native disabled when unavailable; adjacent explanation available outside disabled focus target.  | Permission absence removes the action; business restriction explains why an otherwise authorized action is unavailable.    |
| Loading         | Reserve dimensions; status label; skeleton is decorative content inside one status region.       | Cancel stale reads; lock only the affected mutation; never render unknown metrics as zero.                                 |
| Empty           | Differentiate no records from no filter matches and no permissions.                              | Offer the allowed next step or clear-filter action; no invented operational success.                                       |
| Error           | Inline textual error plus field association and summary when multiple errors; preserve draft.    | Retry bounded reads; for uncertain mutations refetch state before replay. Move focus to summary only after submit.         |
| Success         | Persistent changed state plus polite concise confirmation; retain receipt/reference.             | Toast is supplemental. Save acknowledgement may stop sticking after 3.5s because saved state remains in normal flow (E10). |
| Stale/offline   | Show last successful timestamp and “Updates paused/Last location…” with retry.                   | Keep last known records usable; suppress misleading current-location markers.                                              |
| Deadline        | Explain a real offer expiry and timezone; avoid announcing every countdown tick.                 | Do not promise adjustable server offers where availability is essential; assess essential-time exception per process.      |

Keyboard sequence: skip link → navigation → page title/content → filters → list items → contextual actions. Opening a modal moves focus to its title or first meaningful field, makes background inert, traps Tab/Shift+Tab, closes with Escape if cancellation is allowed and restores the opening control. Modal footers stay visible without hiding focused inputs. A fullscreen map must return to its original place and restore scrolling; the current shared map provides a foundation (E05), not proof of every device's behavior.

## 6. CSS, architecture and performance debt

1. **Token split:** root uses Segoe UI and its own palette (`design-system.css:2`), while admin overrides font/palette (`adminWorkspace.css:1`). Design-lab tokens must be scoped under its own root, then deliberately promoted component by component after regression review. Do not append another global palette.
2. **Broad legacy selectors:** `.welcome h1` at `styles.css:59`, another `.welcome` region at `styles.css:1986`, and admin overrides at `adminWorkspace.css:477` create cascade coupling. New code should use component classes/data variants; replace one shared primitive at a time and remove superseded rules only after checking all roles.
3. **Unsystematic scale:** sampled admin rules include 10,11,12,13,14,15,17,19,21,22,27 and 36px, with varying gaps/radii. CSS selectors at `adminWorkspace.css:151`, `:524`, `:729`, `:1832` illustrate drift. A written modular scale does not migrate these rules by itself.
4. **Touch debt:** legacy dispatch/payment/mobile/editor rules include 40/42px controls (`styles.css:1336`, `:1498`, `:2103`, `:2215`), and admin uses 44/46px (`adminWorkspace.css:204`, `:253`). These need measured width _and_ height review against the requested 48px product target.
5. **Pagination debt:** Orders asks for 100 and never requests another page (E09). Staff/audit/payments consume first pages (E18, `PaymentOperations.jsx:23`, `PaymentController.php:86`). The dashboard intentionally previews 8 of a capped 100 deliveries (`AdminWorkspace.jsx:374`, E23). Preserve preview labeling; implement real pagination/filter totals rather than loading an unbounded dataset.
6. **Polling and focus:** order polling every 5s and offer countdown every 1s are useful operational mechanisms (E09/E20), but must not reset focus, announce whole lists, reorder active controls unexpectedly or lose user-entered prep fields. Pause decorative motion and hidden-page work; preserve essential deadlines. Use one data resource per route, cancellation and controlled stale-cache behavior.
7. **Map/canvas cost:** lazy loading and a stable fullscreen map avoid duplicate Leaflet instances (E05). Keep the 3D reservation view optional and a 2D/list alternative available (E11); defer Three.js until requested. Do not preload every role's heavy screen for a landing page.
8. **Prototype separation:** preview entry `frontend/design-lab.html` and `frontend/src/design-lab/DesignLab.jsx:1424` are present as an independent source entry. `frontend/src/design-lab/main.jsx:4` imports preview composition and its styles instead of production App/api; `frontend/vite.config.js:10` includes both HTML build entries. Role views use `?view=landing|administrator|manager|cashier|kitchen_staff|waiter|rider|customer`; these do not create production role routes. Source review confirms local state demonstrations; runtime/browser acceptance is a separate QA result. Existing React/JSX/CSS stack is retained; no wholesale TypeScript conversion or new UI framework is required to deliver the design specification.

## 10. Verification and staged adoption

1. Freeze source fixtures and policy assumptions; expose the discrepancy register in the preview. Verify no production API client is imported into preview mutation flows.
2. Run lint/build, interaction units for fixture adapters/math and DOM behavior, and desktop/tablet/mobile browser checks on the separate preview. Verify 480px and narrower modal layouts, real keyboard Tab cycles, Escape and close-focus restoration.
3. Sample 375,390,430,768,1024,1280 and 1440px, then zoom 200%/400%, text-spacing overrides, landscape, high-contrast/forced-colors, reduced motion and slow/offline/provider failure. Test at least NVDA+Firefox/Chrome and VoiceOver+Safari on complete flows before making conformance statements.
4. Migrate common atoms, then route templates, preserving API contracts and role tests. Review customer/rider paths after each global token change. Add pagination at the data layer rather than merely hiding overflow.
5. Backend features require their own validation: cash shift concurrency/audit, staff attribution/session checks, deposit idempotent refund lifecycle, policy version history, currency rounding/provider constraints and outlet tenant scoping.
6. Publish a test report naming tested routes, versions, devices, criteria, exclusions and unresolved failures. Maintain this applicability register as new content, providers and workflows are introduced.

Architecture/UX trade-off: preserve existing server authority and task permissions while evolving shared presentation in small, verifiable stages; prototype breadth is never represented as production capability.
